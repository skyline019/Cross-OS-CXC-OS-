\chapter{受限文件系统的恢复、查询与软件写入开销}
\label{chap:current-evidence}

本章以 xv6 的教学内核为对象，研究固定挂载点上的文件操作、版本化对象图及可重复的软件路径计数。它不是完整 POSIX 文件系统，也不是对物理掉电的一般性证明。文件内容经 KV run 保存，并保留内容定义分块（CDC）与 stream；这些组合及其变体不应被表述为对已有 COW、持久内存文件系统或过滤索引的首创。持久内存文件系统和字节寻址一致性的相关研究可参见 \cite{pmfs2014,nova2016,bpfs2009}。

\section{实现边界与设计}

VFS 保留原生 xv6 根，将 \texttt{/pm} 作为固定挂载点，按组件解析路径；目录引用与普通文件描述符固定底层 inode。独立打开同一 PM inode 时共用工作缓冲而各自维护偏移；\texttt{dup}/\texttt{fork} 的同一打开对象共享偏移。普通文件支持同后端硬链接及共享 inode；打开文件的非最后链接可以移除，但删除最后链接的 unlink-open 仍不支持。当前没有动态挂载、符号链接、跨后端重命名、权限或 \texttt{mmap}；文件大小上限 1024 字节，运行路径仍由全局 PMFS 锁串行化。

元数据使用不可变 inode 和 dentry 快照，双槽 checkpoint 指向完整对象图。非替换重命名只改变 dentry 图，因而追加一个新 dentry 页并复用已提交的 inode 页；替换已有目标仍需同时产生两页。文件内容同步先发布新 KV run，再发布新 inode 快照，并复用未改变的 dentry 根。该设计要求旧根始终指向不可变且未回收的页。元数据分配现在验证并保护两个 checkpoint 的根和完整 run 链，仅复用两槽都不可达的页；run 仍追加，故 KV 追加空间最终可能耗尽。

普通文件先预探测 CDC 切分：当块数不超过四个 extent 且不多于 256 字节固定分块时采用 CDC，否则以固定分块兜底。此策略保证有界文件可表示，并不实现内容去重，也不保证所有输入的 CPU 开销降低。KV 冷查询首先查有界精确索引；超过 512 个已跟踪键后，未跟踪键使用完整的 newest-first fallback。coarse posting 对所有已提交键维护，fallback 倒序枚举置位的 run，再经过 Bloom 和 fence 判断。更新已经跟踪的键即使在索引满后也必须刷新指向。

\section{显式压缩与延迟回收}

受 FractalClusterStore 的不可变 run 和提交后延迟释放思路启发，本实现对当前完整 run 链执行有界归并，按键保留最新公开值、活跃 inode 引用的 chunk 及 chunk 编号高水标记；预检足够的尾部空间后写入不重叠新链，通过一个 checkpoint 发布并重建索引。旧链必须保持到前一槽被后续提交替换。实现并非该项目完整的分层/增量维护机制，也不声称相关算法首创。

在三核 EMUL 指定工作负载中，90 个 run 经压缩成为 19 个，688 条输入记录归并为 606 条输出记录，额外写出 19 页；一个未进入精确索引的冷键从 17 次候选 run probe 变为 2 次，但两者均读一页。源页缓存消融的软件读请求字节为 3084288 与 921600；这些是单个确定性负载的内核计数，而非时间、物理介质流量或通用加速比。压缩自身产生写流量，并要求空间和停止活动文件流。

\section{恢复实验与尚未解决的问题}

上一轮三核共享内存后端分别执行非替换与替换子树重命名的 43 次启动，以及文件/KV 的 62 次启动；实验性 QEMU NVDIMM 后端及其 Zicbom 指令路径分别执行同样的测试。检查器覆盖指定的半页、整页与 checkpoint 软件切点、旧/新内容及多次重启。模拟未覆盖任意指令位置或物理缓存失效；普通共享文件与杀死 QEMU 进程也不能证明宿主断电后的持久性。有界规格模型枚举旧/新结果并验证负控，但尚未从真实内核提取完整 store/flush 轨迹。

剩余的软件问题包括新 run 页的安全复用、near-full 维护预留与分步回收、固定 checkpoint 槽的热点、可扩展并发以及更完整的 VFS 语义。软件页写、flush 行请求不能称为 NAND 擦除、器件磨损或真实介质写放大；没有真实设备证据时不得声称已实现磨损均衡或提升了硬件寿命。原生 xv6 对照也没有与 PMFS 等价的设备持久化边界，故现有 TCG tick 不能支持硬件性能优越性结论。
