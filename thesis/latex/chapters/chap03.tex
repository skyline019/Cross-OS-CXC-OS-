\chapter{系统设计}
\label{chap:design}

\section{产品形态与非目标}

PMFS 的产品形态是：\textbf{并行于 virtio 根的字节寻址文件子系统}。用户态通过 \texttt{pmfs\_create}/\texttt{mkdir}/\texttt{fopen}/\texttt{fread}/\texttt{fwrite}/\texttt{fsync}/\texttt{readdir}/\texttt{funlink} 访问文件对象；并保留 \texttt{put}/\texttt{get}/\texttt{seal} 作批量引擎与融合证明。\textbf{不}替换根 FS，\textbf{不}做完整 VFS。

明确非目标：挂载替换 `/`；真物理 NVDIMM 驱动主线；并入 FCS/Aurora 源码树；\texttt{lseek}/\texttt{mmap}/\texttt{rename}/硬链接；多写者字节范围锁。

\section{软件分层}

自上而下：

\begin{enumerate}[leftmargin=2em]
  \item 用户 API：文件 \texttt{create/mkdir/open/read/write/fsync/readdir} 与 KV \texttt{put/get/seal}；
  \item \texttt{pmfile}：目录树 + extent 元数据（inode/dentry 页，magic+校验）；
  \item \texttt{pmcdc}/\texttt{pmstream}：Rabin 式滑动哈希切分与窗口刷写（Fixed 模式供消融）；
  \item \texttt{pmalgo}：chunk$\to$memtable$\to$不可变 run、B1/B2/B3、融合计数 \texttt{fuse\_*}；
  \item \texttt{pmindex}：量化键、posting、查询 LRU（qcache）；
  \item \texttt{pmfs}：双槽超级块与 commit；
  \item \texttt{pmdev}/\texttt{pmem\_persist}：行级 flush+fence，落 EMUL 或 MAP 窗口。
\end{enumerate}

盘上布局：页 0/1 为超级块双槽；页 2/3 为 inode/目录项元数据；其后为 run 数据页。文件内容不以页内联为主，而以 KV chunk（extent）承载，保证与索引核同一提交路径。容量边界由实现常数约束：约 \texttt{PMFILE\_MAX\_INO}${}={}$40、\texttt{PMFILE\_MAX\_EXT}${}={}$4、\texttt{PM\_VAL\_MAX}${}={}$512，单文件量级约 2\,KiB（刻意不声称大文件生产能力）。

\section{刷写协议与双槽提交}

持久化协议固定为：
\[
  \mathrm{store}\ \rightarrow\ \mathrm{flush}(64\mathrm{B\ lines})\ \rightarrow\ \mathrm{fence}
  \ \rightarrow\ \mathrm{store\ SB}\ \rightarrow\ \mathrm{flush}\ \rightarrow\ \mathrm{fence}.
\]
文件路径上，\texttt{fsync} $=$ 刷 stream 窗 + 写 inode/dentry 页 + \texttt{pmfs\_commit}。提交以 \texttt{seal}/commit 为显式边界：批量 \texttt{put} 进入内存表后，\texttt{seal} 将 run 持久化并原子翻转活动超级块槽位（epoch + 校验）。设计保证：半写活动槽可检测并回退；未提交数据对读路径不可见；索引可自 run 重建。

\section{CDC、stream 与公平消融}

文件写流经 Rabin 式 CDC 切分为 chunk（定长 Fixed 仅作对照），再经 stream 窗口聚合后 \texttt{pm\_put}；flush/seal 边界由策略开关控制。公平消融 A0--A4 在\textbf{同一 payload、同一页设备与 KV 核}上只切换「CDC 开/关」与「批量 seal / 每 chunk 立即 seal」，输出 \texttt{cycles} 与 \texttt{wa\_x100} 作为公平面效应量。架构面（相对 xv6 日志栈的量级差）与公平面（策略效应）\textbf{分表陈述、禁止混读}。

\section{写放大与可观测性}

定义
\[
  \mathrm{wa\_x100} = \frac{\mathrm{phys}\times 100}{\mathrm{logical}},
\]
其中 logical 为用户 payload 字节，phys 为整页写入（对齐、run、B3 重写）。小 value（如 8\,B）相对 4\,KiB 页必然放大；该放大与 xv6 日志放大\textbf{不同源}，论文中分开叙述。\texttt{fuse\_puts}/\texttt{fuse\_seals} 用于证明文件路径未旁路 KV 核。

\section{性能对比的设计意图}

实验对比三条路径：PMFS-KV、PMFS-File、xv6 \texttt{fs+log}。File 路径为 $N$ 次小文件 \texttt{create/write/fsync}；KV 为 $N$ 次 \texttt{put} + 一次 \texttt{seal} + $N$ 次 \texttt{get}；xv6 为每键一次小文件 + \texttt{sync}。目的是说明「避免 virtio 日志与块栈」的\textbf{量级}差异，而非宣称同等完整 POSIX 下的绝对加速比。公平面效应量只引用 A0--A4。
