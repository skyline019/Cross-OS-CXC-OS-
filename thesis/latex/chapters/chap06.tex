\chapter{结论与展望}
\label{chap:concl}

\section{工作总结}

本文在 xv6-riscv 上设计并实现了并行于根文件系统的字节寻址 \textbf{PMFS 文件子系统}：目录与 extent 元数据、CDC/stream 切分写入、融合至 KV run/索引核，并覆盖 EMUL / MAP / PMEM2 三种后端。系统以双槽提交、行级 flush+fence、inode 页 magic+校验，以及 \texttt{ONBOX\_PMFS\_*} 契约套件（含 remount 字节等价与故障注入）验收崩溃与掉电语义。

主要结论如下：

\begin{enumerate}[leftmargin=2em]
  \item \textbf{方法学：}相对「再实现一套双槽 PMEM-FS」，教学 OS 上可机器判定的契约套件（含 \texttt{REMOUNT}/\texttt{FAULT}/\texttt{PMEM2}）才是不可替代点；正确性可用一行串口与 CI 复现。
  \item \textbf{系统：}明确崩溃可见点——仅 \texttt{fsync}/提交后写可见；未 sync 写在 remount 后不可见；半页元数据损坏被校验拒绝。
  \item \textbf{实验：}架构面报告相对 xv6 \texttt{fs+log} 的量级延迟/吞吐差；公平面以 A0--A4 同载荷消融给出 \texttt{cycles}/\texttt{wa\_x100} 效应量，二者不可混读。
\end{enumerate}

\section{不足}

真物理 NVDIMM、完整 POSIX（seek/mmap/rename/多写者）、多核并发均未纳入主线。性能数字依赖相对时间单位与 QEMU，外推需谨慎。文件容量受 extent 槽与 chunk 上限约束（见语义清单）。

\section{展望}

\begin{itemize}[leftmargin=2em]
  \item 扩展故障注入（seal 中途杀进程、更多页损坏模式）并保持契约码表稳定；
  \item 在附录路线指引下对接真实 PMEM/NVDIMM 做延迟校准；
  \item 在不破坏尖刺的前提下增强大文件与只读共享语义的可测边界。
\end{itemize}

答辩一句话总结：\textbf{不可替代点是教学 OS 上可机器判定的崩溃/掉电契约套件（含 remount 内容等价）；量级优势来自去块设备路径的架构差，公平面消融另表陈述。}
