\chapter{绪论}
\label{chap:intro}

\section{研究背景}

操作系统存储子系统长期以块设备为中心：文件内容经缓冲缓存、日志与块 I/O 栈落盘，崩溃一致性依赖有序刷写与检查点。教学操作系统 xv6~\cite{xv6book} 以 virtio-blk 与日志型文件系统讲授这一经典路径，语义清晰、代码可阅读，但延迟受块设备与元数据更新约束，且难以自然表达字节寻址持久内存（Persistent Memory, PMEM）上的提交与掉电语义。

PMEM 以字节寻址提供近似 DRAM 的访问延迟，并在掉电后保留数据~\cite{nvmm2021}。学术界与工业界已出现面向 PMEM 的文件系统与编程模型，如 PMFS~\cite{pmfs2014}、NOVA~\cite{nova2016}、BPFS~\cite{bpfs2009}、Mnemosyne~\cite{mnemosyne2011} 等。它们多面向通用或接近生产的 Linux 环境；将完整 POSIX 文件层移植进 xv6 既超出本科毕设合理体量，也易掩盖「如何验收崩溃正确性」这一更尖锐的工程问题。

\section{问题陈述}

本文关注三个相互耦合的问题：

\begin{enumerate}[leftmargin=2em]
  \item \textbf{形态选择：}在 xv6 上是替换根文件系统，还是提供并行的字节寻址键值（KV）引擎？完整 inode/目录层成本高，且与「验证提交与掉电」目标不对齐。
  \item \textbf{一致性模型：}双槽超级块、不可变 run、批量 seal 提交如何保证「未提交不可见、半写活动槽可检测」？
  \item \textbf{验收方法：}如何让崩溃与掉电语义\textbf{可机器判定}（串口一行、宿主脚本、CI），而非仅靠人工读日志？
\end{enumerate}

\section{研究内容与目标}

本文设计并实现 \textbf{PMFS}：并行于 virtio 根的 PMEM 文件子系统（\texttt{create}/\texttt{fopen}/\texttt{fread}/\texttt{fwrite}/\texttt{fsync}）与 KV 引擎（\texttt{put}/\texttt{get}/\texttt{seal}）；后端支持 EMUL、MAP 与 PMEM2。研究目标：

\begin{itemize}[leftmargin=2em]
  \item 映射 QEMU NVDIMM 仿真窗；inode/dentry 去块设备布局；行级刷写协议；
  \item 建立含 \texttt{PERSIST}/\texttt{FILE} 的 \texttt{ONBOX\_PMFS\_*} 契约验收门；
  \item 报告文件 API 延迟中位数与相对吞吐，并记录可复核踩坑。
\end{itemize}

\section{主要贡献}

对照相关工作与作者前序原生项目（FCS / Aurora），本文贡献收敛为一条尖刺与两条支撑柱~\cite{fcsown,auroraown,cxcos}：

\begin{description}[leftmargin=2em,style=nextline]
  \item[尖刺（C1）] 教学 OS 上可机器判定的崩溃与掉电契约套件：阶段码表 + 宿主脚本 + CI。
  \item[系统柱（C2）] 去块设备文件布局 + 行级 persist + 双槽/B3/WA。
  \item[实验柱（C3）] PMEM2 文件后端杀启掉电一行过，作为尖刺在掉电场景上的实例化。
\end{description}

主动不宣称的内容包括：完整内核 VFS、真 NVDIMM 主线化、将 FCS/Aurora 源码并入库。
