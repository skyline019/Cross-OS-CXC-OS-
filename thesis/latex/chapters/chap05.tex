\section{架构面：对齐工作量的延迟与吞吐}

对比两侧使用普通文件 API、相同成功操作数、内容与 EOF 校验；路径深度对齐。PMFS 样本取自 EMUL（易失），默认 flush 为 touch+fence；xv6 \texttt{fsync} 为全局日志同步且无设备 flush。故结果只支持\textbf{去块日志栈的架构级软件路径}叙事。

\section{公平面：软件请求与提示消融}

同 PMFS、同一 \texttt{fsync} 契约下，关闭可达性提示显著增加软件读请求并降低短批吞吐（64\,B 覆写吞吐比约 4.2$\times$，样本有限）。页写请求字节在两组相同，故消融\textbf{不}证明降低物理写入。

\section{维护与空间}

双槽保护下的页复用使指定元数据负载尾部高水位可控；显式压缩可归并 run，但需暂存空间，满盘可安全失败。软件写字节计数不是 NAND 擦除或器件寿命。

\section{实现难点与失败史}

早期基线存在：破坏性 boot 自测改写介质、无条件自动 format、flush 仅遍历、跨进程文件读回失败、旧 bench 工作量不对齐等。v3 改为显式 format、安全挂载、COW 根、重启 oracle 与对齐 bench。细节见仓库踩坑与沙箱记录。这些叙述用于证明系统经故障闭环调出，而非一次性写成。

\section{局限与威胁效度}

\begin{enumerate}[leftmargin=2em]
  \item 设备：补丁 NVDIMM 非上游通用；MAP/共享 RAM 不是 NVDIMM。
  \item 持久域：默认非硬件写回；TCG 无缓存层级；杀进程 $\neq$ 物理掉电。
  \item 性能：契约不等价；单环境 TCG 样本；外推真机需重校准。
  \item 功能：有界资源与粗粒度锁；非完整 POSIX；近满压缩可失败。
\end{enumerate}

\section{本章小结}

实验主线是可复现提交验收与诚实假设；性能服务于架构级软件路径说明；公平面消融不得与架构面 fratio 混读。
