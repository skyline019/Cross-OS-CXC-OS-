# 下一阶段规划（M285–M294 / **A2-SEM**）

> **状态：已完成 / 历史文档（2026-10-29 更新）。** 本计划在 M287–M306 落地，实际结果与偏差见
> [`plan-m307-m316.md`](plan-m307-m316.md) 附录 C。当前主线为 **A2-C（M307–M316）**。

**定位**：本文件是 M285 起十个里程碑的作战计划，**不新增也不放松任何既有合同**。正式中场仍在约 **M294**（届时写 `docs/midpoint-assessment-29.md`）。
**输入证据**：2026-10-28 宿主侧实测，工具为本次新增的 [`tools/cc_conformance.py`](../tools/cc_conformance.py)（附录 A/B 为原始数据）。
**基线**：M284 / v2.80.0（CCDRV：`disk/cc` argv 驱动）。

---

## 0. 结论（先看这四句）

1. **"能跑较为复杂的方言代码"成立，但天花板比看上去低**：递归、循环、`switch`、结构体、全局、`sizeof`、`write` 都真的对（32/59 用例 PASS，含 `fib` 递归 88、冒泡 14、栈机 42）。
2. **真正危险的是一类"编译通过但算错"**：`ptr[i]` 当形参时写进自己栈帧、`char*` 下标按 8 字节步长、指针 `+` 不按元素缩放、`unsigned` 除法按有符号、`write "长串"` 静默截断到 8 字节、以及**词法把未知字符当 EOF**（`#define` 一行就能让整个程序被静默丢掉）。**共 7 个症状、4 个根因（D1/D2/D3/D6）**，其中 `prog_sort_call`（冒泡 + 二分）直接崩溃。
3. **A2 的瓶颈不是"再多几个语法点"，而是三件事**：语义可信度、规模天花板、以及"链接输入里 53/53 个 `.o` 都是宿主预编译种植"这条真实性债。
4. **所以下一个十年只做一条主线：A2-SEM —— 把"能跑"变成"可相信、可扩展、可自证"**。语法扩张（结构体数组、多维数组等）排在语义修复之后，而不是之前。

## 1. 这次是怎么测的（可复现）

`tools/run_cc_host_test.py` 只断言"能不能编译"（59 个 `expect_ok` / 63 个 `expect_fail`），**没有任何"算出来的数对不对"的回归**。这正是静默语义错误能长期存活的原因。

新增 [`tools/cc_conformance.py`](../tools/cc_conformance.py) 补上这一层：

| 步骤 | 做法 |
|---|---|
| 编译 | 用 `CC_HOST` 版前端把用例编成 ET_EXEC |
| 加载 | **重打包** PT_LOAD：`emit.c` 产出的 `p_offset=0xb0` 与 `p_vaddr=0x400000` 不同余（mod 0x1000），**Linux 内核直接拒绝/崩溃**；机上加载器容忍，所以这个问题从未被发现 |
| 执行 | 把 `int 0x80` 就地换成 `syscall`（内核 ABI 就是 Linux-64 号：`write=1` / `exit=60`，同长度 2 字节替换） |
| 判定 | 比对**退出码 + stdout**，而不是"编译成功" |

```text
$ python3 tools/cc_conformance.py
CC_CONF: total=59 pass=32 xfail=27 bug=0 xpass=0 reject=0
```

`xfail` 是**显式记账的已知缺口**（每条带一行原因）；`--strict` 会在"已知缺口开始通过"时报错，逼着把 xfail 改成 ok，防止清单腐烂。

## 2. 现状盘点

### 2.1 能力面（真的成立）

| 面 | 实测结论 |
|---|---|
| 控制流 | `while` / `do..while` / `for` / `if…else if…else` / `switch` / `break` / `continue` / 三元 —— 全对 |
| 运算 | `+ - * / %`、`<< >>`、`! && \|\|`、`== != < <= > >=`、`++ --`、`+= -=`、有符号除法/取模（`-7/2=-3`、`-7%2=-1`）—— 全对 |
| 数据 | 一维数组（含变量下标、`st[sp-1]`）、结构体字段 + `->`（局部指针）、全局变量、`const` 全局、`sizeof(struct)` 紧凑布局 |
| 函数 | 4 参、嵌套调用、递归（500 层 OK）、无参 `main` |
| 文本 | `write "..."`（含 `\n \t` 转义）、`write TAG`、`print`、`input` |
| 预处理 | `#include "x.h"` 真可用（展开 + 去 `CXC_A2` 横幅，深度 4） |

### 2.2 语义面（编译通过但错 —— **P0**）

| 用例 | 期望 | 实测 | 根因 |
|---|---|---|---|
| `ptr_param_index` | 42 | 0 | `parse_stmt` 的 `x[i] = v` 只认"栈上数组"，指针形参也走 `cc_emit_index_store(base_slot)` → 写进自己帧 |
| `prog_sort_call` | 14 | 崩溃 | 上一条的直接后果：`sort(&v[0], n)` 内部 `a[j]=…` 写坏调用者/自身栈 |
| `ptr_char_index` | 105 | 95 | `cc_emit_index_load` 恒定 `shl rax,3`，无元素宽度概念 |
| `ptr_scaling` | 42 | 0 | `p+2` 按字节加，未按 `sizeof(elem)` 缩放 |
| `op_unsigned_div` | 42 | 1 | 除法/取模恒定 `idiv`，`unsigned` 语义缺失 |
| `io_write_str_long` | 全串 | 只输出 8 字节 | `CC_LIT_MAX=8` 静默截断 |
| （额外）`#define N 42` | 编译失败 | **"成功"并产出 152 字节残缺 ELF** | `lex.c` 末行 `else { lx->tok = TOK_EOF; }`：任何未知字符 = EOF |

最后一条是最恶劣的：**任何拼写错误/不支持的字符都会让程序后半段被静默丢弃**，而 `cc_compile_ex` 的 `lx.tok != TOK_EOF` 检查因为词法已经返回 EOF 而永远通过。

### 2.3 规模面（硬墙，全部实测）

| 维度 | 上限 | 用例 |
|---|---|---|
| 源文件 | 16 KiB | `CC_SRC_MAX` |
| 生成代码 | 64 KiB | `CC_CODE_MAX` |
| 标识符 | **20 字符** | `cap_ident_20` |
| 单函数局部 | 56 | `cap_locals_56` |
| 全局 | 16 | `cap_globals_16` |
| 结构体 / 字段 | **6 / 6** | `cap_structs_6`、`cap_struct_fields_6` |
| 循环嵌套 | **4** | `cap_loop_depth_4` |
| 函数总数 | 63 + `main` | 第 65 个 → `code=20` |
| 函数参数 | **4** | `fn_five_args` |
| `write "..."` 字面量 | 8 字节 | `io_write_str_long` |

对照：`user/cxc_cc/parse.c` 自己就有 2097 行、几十个函数和多个结构体 —— 用本方言编它是不可能的。**"能跑复杂方言代码"目前指的是"能跑精心控制规模的方言片段"**。

### 2.4 真实性面（A2 的距离）

| 事实 | 数字 | 出处 |
|---|---|---|
| `job.rsp` 链接输入 | 60 个（4 `.s` + 3 `.c` + **53 `.o`**） | `src/user.cpp:2495` |
| 其中 **宿主预编译种植** 的 `.o` | **53 / 53** | `src/user.cpp:2772` 起、`include/cxc/musl_*_elf.hpp`（51 个） |
| 机上现场产出的 `.o` | 7 个（`a/b/lib/main/t/x1/x2.o`），**不进链接输入** | 同上 |
| `disk/cc` 里的字面量特例 | `if (streq(in,"disk/a.c") \|\| streq(in,"disk/b.c"))` | `user/cxc_cc/cc_main.c:466` |
| 驱动器 `main(argc,argv)` | **不支持**（`fn main(argc,argv)` → fail code 0） | 实测 |
| `#link "x.c"` | 只贡献全局定义，**被 link 的函数不可调用** | 实测（`import fn` + `#link` → code 11） |

**结论**：CCDRV 的"进程边界审计"是真的，但**链接进 `out.elf` 的符号 88% 来自宿主**。这不算 A2 的进展，反而会掩盖前端缺陷 —— 前端缺什么能力，都可以用"再种一个宿主 `.o`"绕过。

### 4.2 每步的"为什么是这个顺序"

- **M285 必须最先**：没有回归网，M286 的重构会把现在的 32 个 PASS 一起改坏而无人察觉。这是"用测试调试"纪律的直接应用。
- **M286 单独一层**：寻址是**唯一**同时影响 `[]`、`*`、`&`、指针算术、结构体字段、数组形参的轴。做完这层，6 个静默错误里的 4 个（含 `prog_sort_call` 崩溃）同时消失，`r1`-类真实程序才第一次能跑。
- **M287/M288 放后面**：整数宽度和聚合类型都建立在 M286 的 `CcType` 上；先做会返工。
- **M290 放在语义之后**：放宽 `CC_LOCAL_MAX` 必须同步改 `cc_emit_prologue` 的 `sub rsp, 448`（`emit.c:543`）；在没有回归网时改栈布局极其危险。
- **M291/M292 是本轮唯一允许碰"真实性债"的位置**，且用**只减不增的计数器**表达，避免"再种一个 `.o` 绕过"。
- **M293 的 ELF 合法化**同时服务于两条路：A2 的机上工具链，和"能把产物拿到宿主复算"（现在只能靠重打包 hack 才跑得动）。

3. 过渡期同时接受 `spawn_cc: 3`（旧）与关系式，**两个变更集后**再删旧常量 —— 不许一步删断言。

## 6. "能独立跑复杂方言代码"的验收定义（建议）

把模糊说法换成可判定的四条，写进 `docs/cxc-a2-dialect.md`：

1. **语义**：`cc_conformance.py` 59 用例 `bug=0 xpass=0`，且机上 `conf: NN/59` 子集（建议 12 个）全绿。
2. **规模**：能一次编译并运行 **≥ 800 行 / 单文件 / 含 5 个结构体 + 3 层嵌套 + 字符串处理** 的程序（相当于把 `user/cxc_cc/lex.c` 缩到 1/3 后原样编译）。
3. **真实性**：链接输入里宿主种植 `.o` ≤ 输入总数的 50%，且该比例**单调下降**。
4. **可移植**：产出的 ET_EXEC 符合 ELF 加载约束（`p_offset ≡ p_vaddr mod p_align`），可以拿到宿主用同一套用例复算。

这四条同时给出"下一个十年成功/失败"的判据，而不只是"又跑通一个 demo"。

## 7. 反范围（这个十年明确不做）

- ❌ 不追 C++ / 模板 / 异常（B 盘项，非一阶段）。
- ❌ 不做优化器、寄存器分配、SSA —— 保持"栈机 + 直译"形态，先把语义做对。
- ❌ 不做完整 C99：依次只做 `C89 子集 → 指定清单`，清单外一律**显式报错**（这是 M285 的核心纪律）。
- ❌ 不用"再种一个宿主 `.o`"解决任何前端缺口。
- ❌ 不改 `--timeout`、不删矩阵行、不用重试换绿（`docs/midfield-cadence.md` 硬契约）。
- ❌ 不在 M286–M290 期间动 `disk/cc` 的驱动形态（避免一次改两层）。

## 10. 并行维护轨（不占主线）

A2 是一阶段第一靶（[`product-goals.md`](product-goals.md)），下面这些只在**不抢主线**的前提下做，且不得以牺牲 A2 为代价"薄切片"：

| 项 | 处理原则 |
|---|---|
| 缺号 syscall / stub 冒充完整功能 | 按债登记；每补一个换掉一个 stub，禁止长期 stub 当实现 |
| 前端产物 → 机上回归 | M293 的 ELF 合法化后，宿主可与机上跑同一套 conformance，避免"两边各测一套" |
| 驱动模型 / 多队列 / TCP | B 盘项，一阶段只保持现状，不扩张 |
| 文档基线同步 | 每个里程碑同变更集更新 `README.md` Status 表 |
