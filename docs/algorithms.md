# 自研算法与性能工程

## 1. 定位

本阶段的算法是为 CXC/OS 当前约束自行设计和实现的，不把常见思想包装成未经证明的“全球首创”。区间分配、大页映射、对齐展开都有计算机科学背景；本工程的自研点是具体的数据布局、物理地址链接、局部合并过程以及与 UEFI/direct-map 切换的组合。

优化遵循：

1. 先建立可复现正确性测试；
2. 再降低元数据写入、扫描和清零成本；
3. 用固定负载观察回归；
4. 不把单次 QEMU TSC 数字当成普遍结论。

## 2. Inline-Extent PMM

### 数据布局

每个空闲区间首页存放两个 64 位字段：

```text
Extent {
    next_physical;  // 下一个更低物理基址的空闲区间
    pages;          // 当前区间页数
}
```

链表按区间物理基址降序排列。节点地址就是区间基址，节点只存在于空闲内存，因此不需要单独的元数据堆，也不会在初始化时写每一个空闲页。

### 不变量

1. 链表按物理基址严格降序；
2. 任意两个区间不重叠；
3. 释放完成后，任意两个可相邻合并的区间不会继续分开存在；
4. 所有区间页数之和等于 `free_pages_count`；
5. `next_physical` 是物理地址，不随 direct-map offset 改变；
6. 已分配页上不允许继续保留有效空闲节点。

`extent_count()` 和随机压力后的账目/区间数检查用于验证这些不变量。

### 初始化

- 从 UEFI 内存图提取 `EfiConventionalMemory`；
- 裁剪到 2 MiB 以上和当前 direct-map 可覆盖范围；
- 排序并合并区域；
- 每个区域只写一次节点。

若区域数为 R、空闲页数为 N，则元数据初始化由上一版的 O(N) 次页写入降为 O(R) 次节点写入；排序成本为当前固定小区域数组上的插入排序。

### 分配

从首个足够大的区间高端取出所需页数：

- 部分分配保留原节点位置，仅减少 `pages`；
- 整个区间分配时摘除节点；
- 支持任意连续页数，不向上取 2 的幂；
- 分配后仍逐页清零，不把安全语义换成未初始化内存。

最坏搜索为 O(E)，E 是当前区间数；常见首个区间即可满足时接近 O(1)，另有实际清零成本。

### 指定物理上限以下的分配

`allocate_pages_below(count, limit)` 用于有窄 DMA mask 的设备，`limit` 是不包含在内的物理地址上限。普通高端分配不能满足这一约束，因此搜索时跳过完全高于上限的 extent，并把相交 extent 裁剪到 `min(end, limit)`。

若上限切开一个 extent：

1. 仍从上限以下的可用部分高端取出页面；
2. 上限以上的 high tail 新建为更高地址的空闲节点；
3. 下限处剩余部分保留原节点，若为空则摘除；
4. 保持链表降序、区间不重叠和总空闲页数不变（扣除本次分配）。

因此不能只把原 extent 的 `pages` 截短，否则会静默丢失 high tail。EDU 的 512 MiB 回归实际分到 `0x0FFFF000` 和 `0x0FFFE000`，两页均满足 28 位 DMA 上限；释放后空闲页数必须精确恢复，后续 PMM 压力与调度测试继续通过。

碎片自测也使用这一接口：先取得并释放 16 页 arena，再限定 8 次单页分配位于 arena 末端以下，并验证返回地址连续。这样测试不再依赖 OVMF 设备拓扑产生的初始内存图；奇偶释放仍必须增加 extent，最终页数和 extent 数必须精确恢复。

### 释放与局部合并

插入时保存两个链接位置：

- 指向当前插入位置的 `link`；
- 指向更高邻居自身的 `higher_link`。

随后：

1. 若低邻居末端等于新区间基址，将新区间向下合并；
2. 若合并后的末端等于高邻居基址，再通过 `higher_link` 摘除高邻居并合并。

这样只需一次查找和最多两次局部合并，不再额外扫描整条链。奇偶释放、固定种子随机释放和批量有序释放都会覆盖该路径。

### SMP 锁域（M10）

分配、受限 DMA 分配、释放/合并和账目快照使用同一 IRQ-safe 原子 spinlock，清零也在 PMM 临界区内。heap 使用外层独立锁，扩容时固定按 heap→PMM 顺序获取，PMM 不反向调用 heap。

多核运行时每个 worker 执行 8 轮页/块分配、跨 worker 内容检查和释放；物理页必须唯一，heap pattern 不得互相覆盖，最终空闲页数扣除 heap 永久扩容后必须精确闭合。当前全局锁以正确性为先，不据此宣称多核分配性能提升。

## 3. Direct Map

- 基址：`0xFFFF800000000000`；
- 过渡 PML4 克隆固件现有顶层项，保证首次 CR3 切换时当前代码和栈不失映射；运行时根表随后移除低映射；
- direct map 的 PML4/PDPT/PD/PT 由内核重新分配；
- 对齐且剩余长度足够时使用 2 MiB 页，其余边界使用 4 KiB 页；
- PMM 节点保存物理地址，所以 CR3 切换后只需更换物理到虚拟的偏移，无需修复整个链表。

大页减少页表层级和 TLB 压力。当前 direct map 已为 NX；higher-half、内核 RX/RO 权限和栈 guard 的实现见 `higher-half.md`。

## 4. 64 位内存例程

页清零曾是批量分配的主要成本。当前 `memset`：

1. 先处理到 8 字节对齐的头；
2. 将字节扩展为 64 位模式；
3. 每次展开写入四个 64 位字；
4. 再处理 8 位字和尾部字节。

`memcpy` 只在源和目标都 8 字节对齐时走展开路径，否则走字节路径。GCC `may_alias` 类型避免把后备字节存储的有效类型当作优化假设。所有偏移和长尾组合都有边界测试。

## 5. 基准口径

固定负载：

- 连续执行 512 次单页分配；
- 逆序释放这 512 页，这是有序释放路径；
- 用 `lfence + rdtsc` 读取起止 TSC；
- 结束后检查空闲页数和区间数完全恢复。

本机 Debug/QEMU 回归参考：

| 阶段 | 分配 cycles/页 | 有序释放 cycles/页 |
|---|---:|---:|
| 修正后的全链二次合并、逐字节清零 | 约 75,042 | 约 3,443 |
| 局部合并后 | 约 73,069 | 约 939 |
| 再加入 64 位展开清零 | 约 6,873 | 约 932 |

这些数字用于说明本工程优化方向，不是严格对照实验：QEMU/TCG、代码布局和 TSC 都有噪声，Release 波动更大。后续优化必须同时通过随机压力，不得只为这个最佳路径调参。

## 6. 后续算法方向

只有在 profiling 证明需要后再推进：

- 按常见连续长度建立区间索引，降低长链最坏搜索；
- direct-map cache-attribute 策略和页表按需构建；
- 每 CPU 缓存与批量释放；APIC、调度和同步原语已具备，仍需 profiling 和账目证明；
- NUMA 区域感知，不能在当前单节点信息不足时伪造策略。
