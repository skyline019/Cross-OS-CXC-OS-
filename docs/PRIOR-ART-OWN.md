# 作者前序原生项目与本课题关系

> 答辩口径：**FCS、Aurora 是作者本人的原生前序工作**；本毕设是把其中**已验证的设计约束**下沉到 xv6 教学内核，并新增**可机器判定的契约/掉电方法学**。不是「抄别人开源 PMEM-KV」。

## 1. 关系图

```text
作者前序（原生）              本课题（xv6-riscv / thesis/pmem-fs）
─────────────────            ─────────────────────────────────
FCS 耐久存储引擎      ──约束──►  双槽 SB / run / B1–B3 / WA
Aurora 索引思想       ──约束──►  量化桶 / 二值 posting / qcache
cxc-os 契约工程       ──手法──►  ONBOX_* 串口门（重写为 ONBOX_PMFS_*）
                              ▲
                              │ 本仓库自研 C 实现 + 新增尖刺
                              │ 教学 OS 契约套件 + PMEM2 掉电一行过
```

## 2. 什么算「自研」、什么算「约束复用」

| 类别 | 内容 |
|------|------|
| 约束复用 | 「只承诺完好 SB」「一提交一 run」「B1 零数据重写分裂」等语义 |
| 本仓自研 | 全部 `kernel/pm*.c`、`syspmfs`、用户探针、QEMU 脚本、契约码表 |
| 本仓新增尖刺 | `ONBOX_PMFS_*` 阶段门 + `contract-pmem2` 文件后端掉电方法论 |
| 明确不入库 | FCS/Aurora/cxc-os 源码树；不 git submodule 拷贝 |

## 3. 被问「是不是移植题」时的标准答

1. 前序是我的项目，解决的是嵌入式/桌面场景；本课题换到 **xv6 教学内核 + RISC-V + QEMU**。  
2. 代码路径不同、语言/运行时不同，是 **约束下沉 + 重写**，不是 diff 搬运。  
3. 顶批差异化在 **契约可机器判定 + PMEM2**，前序项目并未提供 xv6 上的这一套。
