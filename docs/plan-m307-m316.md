## 0. 结论（先看这五句）

1. **M286–M306 是真的有货**：A2-SEM 语义网落地，宿主 `CC_CONF` 59/59 全绿；`planted: 0`（53 个 musl 叶改为机上 `disk/as` 汇编）；ELF 同余、`-E`/`-S`、`DLOC` 诊断都在。**这是从 M284 到 M306 的大跨步，不是刷绿。**
2. **但"59/59 全绿"有 3 个是空的**：`struct_array`、`struct_return`、`multi_dim` 只做**声明**就 `return 0`，从未读写该特性。把这三例改成真读写后，它们立刻变成 `xfail`。**"绿灯"的覆盖面被高估了。**
3. **还有 4 个 P0 是"编译通过但算错/崩"**：`int a[1]` 被当标量 → SIGSEGV；结构体按值传参只拷第一个字段；无类型形参索引字节串按 8 字节步长；`switch` 静默不做 fall-through。这类 bug 比"缺语法"危险得多。
4. **离"能跑真实 C"的最大距离不是算法，是词汇**：实测 60 例普通 C 片段只有 22 例按 C 语义跑对（37%）。缺 `|`/`&`、具名 `enum`、`int a,b;`、`char c='\n'`、`short`/`static`、`typedef struct{…}P;`、全局数组、数组退化、`main(argc,argv)`、函数指针……
5. **所以 M307–M316 只做一条主线：A2-C —— 把"方言自洽"变成"普通 C 程序能跑，且错不了"**。顺序是 **先测准（M307）→ 再修 P0（M308–M311）→ 再补词汇（M312–M314）→ 最后撑规模并上机自证（M315–M316）**。

## 1. 本次复测方法（可复现）

仓内已有 `tools/cc_conformance.py`（M287 起的语义网，`--strict --elf-check --require-exec`），本次在其上加了三样东西，并用**两个外部探针集**从侧面压测"普通 C 到底能不能跑"：

| 手段 | 做法 | 用途 |
|---|---|---|
| 仓内套件 | `python3 tools/cc_conformance.py --strict --elf-check --require-exec` | 基线回归（M306：`total=59 pass=59`） |
| **审计一：诚实性** | 逐条读用例源码，找"只声明不执行"的 `return 0` | 抓**假绿** |
| **审计二：C 表面探针** | 37 例"普通 C 会怎么写"的片段（`int main`/`struct`/`enum`/`\|`/`static`/`argv`…） | 量**词汇距离** |
| **审计三：边界探针** | 23 例定点爆破（1 元素数组、按值传结构体、无类型形参、位运算…） | 定位**静默错值** |

复跑：

```sh

gcc -std=c11 -O1 -w -DCC_HOST=1 -I$R/user -o /tmp/cconf $R/tools/cc_conf_compile.c \

python3 tools/cc_conformance.py --strict --elf-check --require-exec --report
```

## 3. 审计结果

### 3.1 假绿：3 个只声明不执行的用例（**已在本窗修正**）

| 用例 | 旧写法 | 真读写时 |
|---|---|---|
| `struct_array` | `struct S{x;};S a[2];return 0;` | `a[1].x=42` → **编译失败**（数组元素成员访问不解析） |
| `struct_return` | `fn f(){S v;v.x=42;return v;}fn main(){return 0;}` | `q=f()` → **编译失败** |
| `multi_dim` | `a[2][2];return 0;` | `a[1][1]=42` → **编译失败**（两下标读写不解析） |

**处置**：三例已改成真读写并转 `xfail_compile`（带原因），`pass` 从 59 降到 56，`total` 扩到 94。**这类"声明即通过"是本项目纪律（§中场"禁止薄切片"）明确禁止的形态，建议在 `test-contract.md` 里加一条硬规则：任何 `ok` 用例必须至少有一次"读回写入值"或"影响退出码"的断言。**

### 3.2 P0：编译通过但算错 / 崩（4 条，全部已进套件）

| 用例 | 期望 | 实测 | 根因 |
|---|---|---|---|
| `arr_one_elem` | 42 | **SIGSEGV** | `CcLocal.count == 1` 同时表示"标量"和"1 元素数组"：`a[0]` 走标量分支取到值 42，再当地址解引用。反汇编已确认：`mov rax,[rbp-8]` → `add rax,idx*8` → `mov rax,[rax]` |
| `struct_byval_param` | 42 | **40** | 结构体按值传参只复制第一个字段；`(40,2)` 求和得 40，`(1,42)` 得 0 |
| `untyped_param_index` | 42 | **26** | 无类型形参没有 pointee 宽度，字节串按 8 字节步长索引（`slen("hello")` 得 3）。**注意**：`int` 数组经无类型形参是好的（8 字节刚好），所以这条只在字符串/字节缓冲上爆 |
| `switch_fallthrough` | 42 | **40** | `case` 体结束即跳到 switch 尾部（C 是 fall-through）。静默偏差，且文档未声明 |

> 为什么这四条排在最前：它们**不会报错**。`arr_one_elem` 会崩（还算响），另三条静默给错数——这正是"能独立跑复杂代码"最容易被夸大的一类证据。

### 3.3 词汇：普通 C 片段的通过率 22/60

**C 表面探针（37 例）10 例通过**，缺的主要是（按"真实程序出现频率"排序）：

| 缺失 | 后果 |
|---|---|
| `\|` `&` 二元位运算（只有 `\|\|`、一元 `&`） | 位掩码/寄存器操作全部写不了 |
| 具名 `enum E{…}` 与其类型名 | 只支持匿名 `enum {…}`；状态机/错误码风格受限 |
| `int a, b;` / `int x=1, y=2;` | 每个变量都得单独一行 |
| `char c='\n'` `'\0'` `'\xNN'` | 只有 `'A'` 型字符常量 |
| `short` / `long long` / `static` | 类型与存储类缺失 |
| `typedef struct { … } P;` | 只能 `struct P{…};` 之后再写 `P x;` |
| 全局数组 / 全局结构体 | 全局只能标量（`int g[4];` 直接失败） |
| 数组→指针退化（`sum(v,3)`） | 必须写 `&v[0]` |
| `for (int i = 0; …)` | C99 惯用法不支持 |
| `main(argc, argv)` | 无法编"带参数的用户程序" |
| 函数指针 / `union` / `float` / `goto` | 分发表、联合体、浮点、错误跳转都没有 |

**边界探针（23 例）12 例通过**：位运算、字符常量、结构体嵌套、`a[i][j]`、`v.a.x`、`&memset` 类按值细节等即在此集暴露。

### 3.4 容量：实测墙（全部写成 `ok` / `must_reject` 成对用例）

| 维度 | 常量声明 | **实测上界** | 备注 |
|---|---|---|---|
| globals | 64 | **63** | 差一：64 个直接 `COMPILE_FAIL:2` |
| structs | 32 | 32 | 一致 |
| struct fields | 16 | 16 | 一致 |
| 循环嵌套 | 8 | 8 | 一致 |
| 单函数局部 | 128 | 128 | 一致 |

| 标识符 | 64 | 64 | 超过 64 的同前缀两名会被**拒绝**（不是静默合并）✅ |

旧用例名（`cap_globals_16`、`cap_locals_56`…）写的是 M286 之前的墙，已全部改名成实测值并补 `*_over` 负例——**墙必须被断言，而不是被描述**。

### 4.2 为什么是这个顺序

- **M307 必须最先**：现在 `pass=59` 里有假绿、容量用例名写的是旧墙。**在测量工具说谎之前，任何"还债"都无法证明。**
- **M308–M311 单独占四个里程碑**：这四条都是"静默错值/崩"，且都影响后续——尤其 M308（`count==1`）是 `CcLocal` 的模型缺陷，M310（pointee 宽度）是 `CcType` 的最后一公里。**先语义再词汇**，否则 M312–M314 每加一个语法点都会踩在错的地址模型上。
- **M312–M314 按"真实程序出现频率"排序**：位运算/枚举/多声明符字符常量 > 类型与存储类 > 函数指针。**不追求 C99 全集**，只追求"写一个 500 行的工具能编"。
- **M315 排在词汇之后**：扩容量要动 `cc_emit_prologue` 的固定 `sub rsp`、`g_elf_buf` 与各表上限；在语义未稳时动栈布局等于自找回归。
- **M316 才上机**：机上跑语义用例需要新的 `disk/conf` 二进制 + job，属于"只增不减"的合同扩张，放在中场统一收口。

## 6. 验收定义（可判定，替换"能跑复杂代码"这种说法）

0. **不存在假绿**：每条 `ok` 用例都至少读回一次写入值或影响退出码（M307 已建立基线，`test-contract.md` 建议同步）。
1. **语义**：`bug=0 xpass=0 reject=0`；`xfail` 从 30 单调降到 0；**机上** `CONF: 12/12`。
2. **词汇**：C 表面探针 60 例 ≥ 54 例按 C 语义跑对（当前 22）。
3. **规模**：单文件 ≥ 800 行、≥ 100 函数、含全局数组 + 结构体表 + 字符串处理的程序可编可跑（当前上限 63 函数、无全局数组）。
4. **真实性**：`planted == 0` 保持；`inputs_s`/`inputs_c` **由表长推导**；汇编文本来源在文档中如实标注（当前由宿主 `gen_plant_src.py` 生成）。

## 7. 反范围（本十年明确不做）

- ❌ 不做浮点（`type_float` 改成**明确报错**而不是"以后再说"）。
- ❌ 不做 C++/模板/异常/优化器/寄存器分配——保持栈机直译。
- ❌ 不做完整 C99/C11；只做 `C89 常用子集 + 明确清单`，清单外**必须报错**（禁止静默）。
- ❌ 不用"再加一个种植 `.s`"解决前端缺口（`planted` 锁不可回退）。
- ❌ 不改 `--timeout`、不删矩阵行、不用重试换绿。
- ❌ M308–M314 期间不动内核侧（`src/user.cpp` 的 job 形态）与 `disk/cc` 驱动层，避免两线同时回归。
