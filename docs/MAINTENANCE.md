# PMFS 双槽可达性回收与显式 COW 压缩

> 本文是受限 xv6 原型的软件协议及其已测试范围，不是硬件掉电证明、完整文件系统 GC 或磨损均衡。所有 `make` 重建、`test-xv6.py` 和格式化命令必须在**可丢弃的 checkout 与镜像**中运行。量化、负控及逐启动日志见[本轮实验](results/2026-10-28-gc/README.md)。

## 范围与接口

- 持续保留 KV、CDC/stream、Bloom/fence 与有界索引。新 run 可分配于**两个有效 checkpoint 的完整对象图均不可达**的连续页；没有合适空洞时才增长 tail。单次 seal 和完整压缩都先预留，再写页。
- 旧 run 页在两个槽都不再引用后，可用于新的 inode/dentry **或 run**。run 页不可在仍被任何有效槽引用时原地覆盖。支持原 v1 `previous < page0` 物理递减链；仅在复用导致此前驱页不低于当前页时写 run-header v2，并以严格递减的逻辑序号、页集合、checksum 和范围检查防环及重叠。
- 用户可显式运行 guest 命令 `pmcompact`，或调用 `pmfs_compact()`。成功返回 `0`；`PM_COMPACT_BUSY=-2` 表示共享 KV memtable 非空、存在 PM 文件句柄或活动 stream；`PM_COMPACT_NOSPACE=-3` 表示没有足够不相交的连续暂存页；`-1` 为不可用、验证失败等错误。它不替其他进程暗中 seal，不自动执行，也不保证在线低延迟。
- 目录 fd/cwd pin 不引用文件内容 stream，故不会单独阻止压缩；普通文件 fd（即使干净）和专用文件句柄都会阻止。PMFS 全局 sleep lock 串行化维护、文件和 KV 操作；调用期间其他 PMFS 操作等待。
- 默认 8 MiB EMUL 仍是易失内存；MAP 及实验 QEMU NVDIMM 的持久性限制不变。删除文件或压缩后未必马上释放空间；没有自动压缩或低空间预留，受活跃页、连续空洞、256 run 和显式维护时机限制，长期负载仍可能失败。

## 可达性与复用顺序

checkpoint 有 inode 根、dentry 根、run 链头和高水位 `tail`。一次元数据分配在 PMFS 锁内执行：

1. 读取两个槽的提交状态和校验。无效/半写槽无可用根；若有效槽的范围不合法、活动槽不等于当前内存根，或者任一有效槽的 run 链无法验证，则该次分配失败关闭。
2. 分别遍历两个有效槽的 run 链，校验页面、checksum、记录范围、键和序列顺序及链内页重叠；把两个链和两个槽的 inode/dentry 根并入受保护位图。元数据根与任一 run 页相交也被拒绝。
3. 在 `[PMFS_DATA0, tail)` 扫描位图，元数据事务同时预留至多两页；run 和压缩输出逐个预留所需连续区间，同批前面选中的页也即时加入保护。若不足，才在 `tail` 追加余量；整批预检失败不改根或写页。选择游标在内存中轮转，只是逻辑分配策略，**不是持久硬件磨损均衡**。
4. 先写并请求持久化所有新页，再失效非活动槽、写新头、最后发布对齐 8 B 提交词。成功后旧活动槽仍可恢复，下一次扫描必须继续保护它。直到该槽被后续提交替换，原来的独有页才可成为候选。
5. 普通写页错误恢复旧内存根与 tail；新写的但不可达页可在下次分配中重新选择。故障恢复从有效槽重建索引和空闲可达性，不依赖持久化的空闲链表。

run 链不可变时，两个槽各缓存其已验证的 run 位图及被验证的 tail 下界；每次分配仍重新检查槽头及元数据根。元数据提交可复制同一已验证图的提示；单 run seal 仅在预留安全、提交成功且读回校验新 run 的序号与前驱后，将新页合入旧槽图。其他根变化、tail 缩小或重新挂载时回退全链验证。`PMFS_GC_NO_HINTS` 只用于禁用上述传播提示的消融，仍执行双槽安全扫描。此优化依赖**已提交 run 不在仍可达时被修改**；它不主动检测缓存建立后才出现的任意介质位翻转或恶意篡改。校验和也不是抗攻击完整性保护。实验覆盖离线损坏旧链后首次分配必须失败；不能据此声称检测所有在线介质损坏。

## 完整链压缩

1. 在持锁且无待处理 memtable/文件 stream 时，枚举当前链中最多 `256 × 32 = 8192` 条记录的位置，并重新验证源页。两组有界静态位置数组经自底向上归并排序，按 key 升序、run 新旧降序选每个 key 的最新值；不在内存复制全部 value。
2. 所有公开 KV 的最新值保留；内部 chunk 仅保留**当前已提交 inode extent 引用**的记录，并校验引用存在且长度一致。额外保留历史中编号最高的内部 chunk，即使它已删除，作为重启后的 chunk-ID 高水标记，防止重新使用旧编号。
3. 按最多 32 条记录组成输出 run，预先计算各自页数并对所有输出完成批量连续页预留；不够则不写页、不改根。顺序读取源页时复用最近验证的源页缓冲，减少相邻记录反复读同一页。输出可能位于回收空洞或追加区，逻辑序号递增，新链的首个 `previous` 为 NIL。
4. 所有输出页写完并请求持久化后，只提交**一次**新 run 根。旧 checkpoint 指向旧链，仍完整保留；提交成功后重建精确索引、posting、Bloom 和 fence。若发布后重建验证失败，停止服务该挂载，而不是把已提交状态假装回滚。
5. 压缩将活跃视图写到不相交的暂存页，会产生额外 I/O；只有下一次有效槽轮换后，旧链才成为元数据或新 run 的候选。需要足够连续暂存空间，因此接近耗尽时可能返回 `NOSPACE`；它不是能在完全满盘原地清理的全设备 GC，也没有后台调度、预留池或分步维护。

该设计受 [FractalClusterStore 固定提交 b137dc0](https://github.com/skyline019/FractalClusterStore/tree/b137dc0097a7e7b594018590e0d61a24b01eb8c0) 的不可变 run、维护前处理未提交写、提交后延迟释放和维护空间预留思路启发；当前是独立、有界的 xv6 C 实现，不是 FCS 的 cell/segment/manifest、分层或增量 compaction 实现，不声明算法首创。当前只做全链预检，并**未**建立 FCS 式可持续维护空间预留。

## VFS 硬链接及格式兼容

PMFS 普通文件支持同后端 `link`；目录及跨后端链接仍拒绝。多个名字共享 inode、普通打开缓冲和 `fstat.ino/nlink`。去掉非最后一个链接即使文件被打开也可成功；最后一个名字仍被打开时不支持 unlink，也不能替换掉该最后链接。重命名到同一 inode 的另一名字是 no-op；替换有多个名字的目标时仅移除该名字并减少目标 `nlink`。专用脏 stream 在提交内容时沿用最新已提交 link count。

v3 checkpoint 与页字段布局未更改，但 inode/dentry 验证从“一 inode 一 dentry”扩展为普通文件的多个链接；复用产生非物理递减前驱时，run 页使用新增的 run-header v2（这不同于已废弃的**文件系统格式 v2**）。旧版 v3 内核不支持多链接 inode 图或 run-header v2，应拒绝挂载相关快照；**不提供降级迁移**。不要用旧内核处理新镜像，先备份。现有容量、路径长度、锁与故障模型限制仍适用。

## 可观测性及局限

`pmstats` 中 `gc_scans`、`gc_trace_runs`、`gc_reused_pages`、`gc_reused_run_pages`、`gc_failed_scans` 和 `compact_*` 是重启即清零的软件活动计数；两种 `reused` 分别计元数据和 run 页的分配尝试，包含之后回滚的尝试。`tail_pages` 是追加高水位，不是活跃占用，也不会因回收而缩小。`compact_output_pages` 和 `dev_write_bytes` 表示写请求，不是器件磨损或物理写放大。固定双 checkpoint 的提交词仍是热点。

恢复 oracle 在软件页/提交词边界杀死 QEMU，覆盖正常、双槽回退、反复写页后返回错误、旧链损坏及低空间；实际内核变异负控检查错误回收与旧 KV 版本选择。另有[测试构建的实际 PMFS 操作轨迹重放](TRACE-REPLAY.md)，在明确假设下采样行级写回、部分 store 和 drain 前后镜像；它不是逐 CPU 指令跟踪。所有结果仍依赖 atomic commit word、正确持久域和顺序等假设；普通文件后端、SIGKILL、TCG 的 Zicbom 均不能模拟物理掉电或证明真实硬件寿命。
