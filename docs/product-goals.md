# CXC/OS 产品目标（M76 起锁定）

**生效**：Milestone 76 起；与 [`phase1-assessment-roadmap.md`](phase1-assessment-roadmap.md)、[`midfield-cadence.md`](midfield-cadence.md)、A2 合同兼容，不替代既有 PASS/`peer_ok` 冻结面。

## 1. 一阶段主靶（不变）

| 优先级 | 目标 | 含义 |
|---|---|---|
| **第一** | **A2** | **不依赖宿主机**：在 CXC/OS 上用完整工具链（**g++/gcc**）编译并运行任意（合理范围内）代码 |
| **第二** | **B** | 生产级 OS（驱动模型、隔离、运维、多平台证据等） |

一阶段验收口径仍是：机上编译器可用，而不是「宿主交叉编好再拷进 ESP」的 A1 终点。A1 已证明的路径只作脚手架，不得再当作放弃 A2 完整能力的理由。

## 2. 客体与宿主形态

| 面 | 裁定 |
|---|---|
| **客体（guest）** | **ELF 系统**：用户态以 ELF 加载与运行为主路径；syscall 面以支撑 musl/工具链为先，可含 CXC 扩展 |
| **Linux 兼容** | 能跑与已实现 syscall 匹配的 **Linux 静态 ELF**（含 musl-gcc 产物）；完整 POSIX **不是**一阶段宣称范围，但缺号须按债修补，禁止长期 stub 冒充完整功能 |
| **Windows 兼容** | **宿主**：Windows（MinGW）与 Linux 均可构建内核/镜像/合同；**客体 PE/Win32 ABI** 为后续可选轨，不阻断 A2 |
| **设计自由** | 允许与 Linux/Windows **不同** 的内部结构、算法与性能策略（调度、VFS、块缓存、内存等）；兼容看对外合同与可加载 ELF，不要求内核克隆 |

## 3. 完整功能优先（反薄切片债务）

1. **大跨步交付完整能力层**（例：持久 virtio-blk 读写 API，而非一次性探针后拆除设备）。
2. **禁止**因「本切片只要串口 PASS」而拆掉、禁用或放弃通向 A2 的完整路径（存储、可写根、足够 POSIX）。
3. **遇瓶颈**：先留 **调试点**（stage/failure/计数），再 **修补遗留债务**，再实现完整功能；禁止只靠缩小范围或删合同「绕过」。
4. **边缘合同**与成功路径同权（[`test-contract.md`](test-contract.md) §8）。

## 4. 与块设备 / 根文件系统的关系

A2 硬依赖：**可写持久根** + 足够文件/进程/内存 syscall。块设备大跨步（M75 探针 → M76+ 持久读写 → 可挂载根 → 工具链落盘）是一阶段主线，不是旁路演示。

## 5. 冻结不变量

- `CXC_OS_SELF_TEST_PASS` + `peer_ok=1`；M13 Echo 字符串不改写。
- 合同只增不减；修根因，禁止超时/删断言刷绿。
