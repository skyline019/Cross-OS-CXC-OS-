# PMFS v3：支持的文件语义与边界

> 本文描述当前软件子集，而非完整 POSIX 或物理掉电保证。执行平台、故障模型和测得覆盖见[修复与验证报告](PMFS-REPAIR-REPORT.md)。

## 1. 格式、挂载与数据保护

- 默认 EMUL 每次启动初始化内核静态 8 MiB 缓冲，是**易失**存储；普通 MAP 使用 `PHYSTOP` 后的普通 guest RAM，不是 NVDIMM。普通 MAP 用 QEMU virt 的固件 DTB 地址作 RAM 上界保守近似，不是设备发现。实验性 `PMEM_NVDIMM` 则在页分配器启动前读取补丁 QEMU 写入的私有 FDT 节点，验证固定设备地址与大小；这不是通用 NVDIMM/ACPI 发现。所需设备、地址或窗口不可用时均失败关闭，不降级为 EMUL。
- v3 checkpoint 存放双槽、epoch、根、tail 和校验；run 及 inode/dentry 快照追加写入。恢复重建 run/index 并检查边界和完整性。正常 MAP 启动不格式化，也不运行破坏性自测；无有效 checkpoint、旧格式或不可恢复损坏时拒绝挂载。不能承诺检测所有 32 位校验和碰撞或恶意伪造。
- `pmformat --force` 对**未挂载**的目标做破坏性格式化；先备份。它不迁移 v2，也不能对已挂载的文件系统进行在线重格式化。试验目标 `contract*` 开启的旧自测会改写镜像，只能用于 disposable 数据。
- 分配器及 run 只追加，不提供安全回收或 compaction。删除文件并不归还介质页；达到容量、run、索引或 inode 上限后调用失败，不能当作生产系统。

## 2. 普通 fd 适配器

`/pm` 和 `/pm/...` 的**绝对路径**被显式路由；不是通用 VFS 挂载，`/pmx` 不匹配。文件支持 `open`（`O_RDONLY`/`O_WRONLY`/`O_RDWR`、`O_CREATE`、可写 `O_TRUNC`）、`read`、`write`、`fsync`、`fstat`、`close`，以及路径级 `mkdir`/`unlink`；`dup`/`fork` 共享同一打开文件及偏移。打开文件的 `unlink`、第二个独立打开（包括只读打开）会失败，避免不同缓冲相互覆盖。`O_TRUNC` 在打开时提交空版本；创建可能先提交空文件，再返回 fd。

普通 fd 持有最多 1024 字节的工作缓冲，读取/写入共享顺序偏移；超过上限返回错误，文件提交时固定 256 字节分块以适配最多 4 个 extent。读能看到该打开对象自己的未同步修改。最后一个引用关闭时尝试同步并传播错误；若最后 `close` 失败，fd 已关闭且缓冲丢弃，因此需要可重试时应在关闭前检查 `fsync`。进程退出时系统会尝试关闭普通 fd，但退出状态不能报告所有自动关闭失败。

`mkdir`、创建、`unlink`/空目录删除返回成功前提交元数据；可见的每个 checkpoint 引用完整的旧或新对象图，具体成功后的掉电保证仍依赖下文的平台假设。一个操作中断可产生未引用的追加页，不能据此推断所有中间写入均不存在。

**不支持：** 普通目录 fd/`ls /pm`、`chdir /pm`、相对路径路由、`lseek`、`O_APPEND`、`rename`、硬链接、符号链接、权限、`mmap`、跨文件原子事务、同时独立打开同一文件及替换根文件系统。目录遍历使用专用 `pmfs_readdir`，不是 POSIX `getdents`。

## 3. 专用接口与资源

专用 `pmfs_*` 文件/KV 调用仍可用，返回码和读取方式与普通 fd 不完全相同。专用文件句柄属于当前进程，不通过 `fork` 继承；进程退出会丢弃其未同步内容。专用文件 `fwrite` 在一次新打开后的首次写入从文件开头**替换**版本，后续写入按流追加；`fread` 从版本开头读取，而非维护 POSIX offset。`pmfs_fclose` 的失败返回给调用者并保留句柄；部分流错误可能需退出进程丢弃，不能保证无限重试能成功。

主要常量：40 个 inode（含根）、8 个专用/普通共享底层打开槽、每文件 4 个 extent、文件最多 1024 B、文件名数组 28 B、KV 值最多 512 B、最多 256 个 run。实际可用容量还受目录、索引、页分配和专用 CDC 切分影响；错误必须检查，不能从常量推断任意序列都一定可写满。

## 4. 同步与崩溃假设

- 未成功同步的修改**不承诺**故障后保存，也不保证一定丢失。成功的文件 `fsync` 在当前软件协议内先写入/请求持久化数据和元数据，再用双槽 checkpoint 的 8 字节提交词发布；`fsync` 失败不会被包装成成功。共享全局 KV memtable 的其他待处理项目可能被某次 seal 一起发布，故不能把未同步作为隔离保证。
- 全局 `sync()` 先等待 xv6 块日志，再对当时已发布的普通 PMFS fd 快照逐一同步；遇到错误返回失败。它不是所有文件的单一原子事务，也不覆盖专用句柄中尚未同步的工作缓冲。普通 xv6 inode 的 `fsync` 复用这个全局 sync；原生 virtio 驱动没有实现等价的设备持久化 flush。
- 协议需要至少：缓存块写回到**所声明的持久域**、屏障顺序、提交词 8 B 故障原子性、映射有效及校验未碰撞等假设。默认仅触摸内存并执行 fence，**不实现实际缓存写回**。可选 `PMEM_ZICBOM` 发出 `CBO.CLEAN` 并假定 64 B 块、合法权限，但是否到达持久域由平台决定。
- 软件 oracle 在各已插桩切点杀死 QEMU，并以相同的共享 RAM 文件或实验性独立 NVDIMM 普通文件后端重新启动；它验证该进程终止模型下的读取结果，**不是**硬件缓存逐出/乱序/撕裂或物理掉电。独立规格模型覆盖有界提前逐出和负控，但没有追踪实际内核内存指令，也不证明所有实现路径正确。
