# PMFS v3：支持的文件语义与边界

> 本文描述当前软件子集，而非完整 POSIX 或物理掉电保证。执行平台、故障模型和测得覆盖见[修复与验证报告](PMFS-REPAIR-REPORT.md)。

## 1. 格式、挂载与数据保护

- 默认 EMUL 每次启动初始化内核静态 8 MiB 缓冲，是**易失**存储；普通 MAP 使用 `PHYSTOP` 后的普通 guest RAM，不是 NVDIMM。普通 MAP 用 QEMU virt 的固件 DTB 地址作 RAM 上界保守近似，不是设备发现。实验性 `PMEM_NVDIMM` 则在页分配器启动前读取补丁 QEMU 写入的私有 FDT 节点，验证固定设备地址与大小；这不是通用 NVDIMM/ACPI 发现。所需设备、地址或窗口不可用时均失败关闭，不降级为 EMUL。
- v3 checkpoint 存放双槽、epoch、根、tail 和校验；run 追加写入，inode/dentry 快照可在保护双槽可达对象后复用旧页。恢复重建 run/index 并检查边界和完整性。正常 MAP 启动不格式化，也不运行破坏性自测；无有效 checkpoint、旧格式或不可恢复损坏时拒绝挂载。不能承诺检测所有 32 位校验和碰撞或恶意伪造。
- `pmformat --force` 对**未挂载**的目标做破坏性格式化；先备份。它不迁移 v2，也不能对已挂载的文件系统进行在线重格式化。试验目标 `contract*` 开启的旧自测会改写镜像，只能用于 disposable 数据。
- 有双槽保护的元数据页复用，以及显式、要求 KV memtable 和文件 stream 均为空的 COW run 压缩，详见[维护设计](MAINTENANCE.md)。旧 run 只有在两个 checkpoint 均不再引用时才可复用为元数据页；run 本身仍只追加，压缩需要额外尾部空间。删除文件不保证立即归还介质页；长期 KV 写入、run/inode 或页容量上限仍可使调用失败，不能当作生产系统。旧内核不能读取包含多个硬链接的 v3 inode 图，不支持降级迁移。

## 2. VFS 命名空间与普通 fd

- 原生根的 `/pm` 是**固定合成挂载点**，不是动态 mount table。原生根中的同名项被遮蔽；`/pmx` 不匹配。绝对路径从原生根开始，相对路径从当前 cwd 开始；路径逐组件查找，不会把不存在的 `missing/../x` 词法约简成 `x`。`/pm/..` 回到原生根，尾随 `/` 要求目标为目录。`chdir`、`fork`、退出和目录 fd 持有/释放 PM inode pin。
- 原生 xv6 名称保留 14 字节历史语义；PMFS **整个后端绝对路径**最多 27 字节（不含 VFS 的 `/pm` 前缀，而不是每个组件 27 字节）。`getdents(fd, buf, bytes)` 返回固定大小的 `struct vfs_dirent`（`kernel/vfs.h`）记录，名称不会静默截断，返回字节数为记录大小的倍数；小于一条记录的 buffer 报错，EOF 返回 0。目录原始 `read` 仍为 xv6 `struct dirent`，遇到超过 14 字节的 PM 名称会报错或先返回已读记录；使用 `getdents`/`ls` 可获取完整名称。原生目录项的 `type` 不填，须通过 `stat`/`fstat` 查询。
- 普通文件支持 `open`（`O_RDONLY`/`O_WRONLY`/`O_RDWR`、`O_CREATE`、可写 `O_TRUNC`/`O_APPEND`）、`read`、`write`、`lseek`、`fsync`、`fstat`、`close`，以及 `mkdir`、空目录删除、PM 内 `rename`。`dup`/`fork` 共用打开对象和偏移；独立 `open` 有独立偏移，但同一 PM inode 共用工作缓冲，未同步写入和 truncate 对其他普通打开立即可见。每次 PM append 的取末尾和有界写入由 PMFS 锁串行化；原生大写入可能分多个日志事务，不能声称跨事务整次 append 原子。
- PM 文件大小上限 1024 B，越界写失败；PM `lseek` 在上限内可越过 EOF，随后写入的空洞以零填充；原生 xv6 不支持空洞写。目录 fd 只支持 `lseek(fd, 0, SEEK_SET)` 重绕。创建可能先提交空文件，再返回 fd；`O_TRUNC` 在打开时提交空版本（已同步的空文件不重复提交）。覆盖写与现有缓冲字节完全一致时仅移动 offset，不新增脏状态；已经存在的脏状态不会被清除。当前文件语义不提供 mtime 更新。专用 PM 文件句柄与普通 fd 对同一 inode **互斥**，以免不同缓冲覆盖；被打开的文件不能删除最后一个硬链接，非最后链接可以删除。工作目录和目录 fd pin 阻止目录目标被删除或替换。
- 每个独立打开对象的最后引用 `close` 时尝试同步其 inode 的共享脏版本并传播错误。若仍有其他打开对象，失败后的脏缓冲保留供 `fsync` 重试；若这是最后一个普通打开，失败后 fd 已关闭、缓冲被丢弃。退出无法报告所有自动关闭失败，因此需要可靠错误处理时应在关闭前检查 `fsync`。

`mkdir`、创建、`link`、`unlink`/空目录删除和 PM 内 `rename` 在成功返回前提交元数据。PMFS 同后端普通文件支持硬链接，`fstat` 返回共享 inode 与当前链接数；目录和跨后端链接被拒绝。重命名两个同 inode 的名字是 no-op；替换多链接目标只删除该目标名，保留其余链接与打开引用。rename 可移动打开的文件或持有 cwd 的目录，重写整个有界子树并以**一次** COW checkpoint 发布；拒绝目录移入自身、路径越界、非空目录替换、已 pin 的目录或已打开文件的最后链接、类型不匹配。普通错误时恢复内存中的旧命名空间；中断可能留下不可达页。故障后持久语义依赖第 4 节的平台假设，不是无条件的掉电保证。

**尚不支持：** 动态挂载、原生或跨后端 `rename`、符号链接、打开后删除最后链接、权限、`mmap`、通用设备接口、跨文件原子事务和替换根文件系统；并发序列尚无完整线性化证明。它是可扩展的 VFS 子集，不是完整 POSIX/VFS。

## 3. 专用接口与资源

专用 `pmfs_*` 文件/KV 调用仍可用，返回码和读取方式与普通 fd 不完全相同。专用文件句柄属于当前进程，不通过 `fork` 继承；进程退出会丢弃其未同步内容。专用文件 `fwrite` 在一次新打开后的首次写入从文件开头**替换**版本，后续写入按流追加；`fread` 从版本开头读取，而非维护 POSIX offset。`pmfs_fclose` 的失败返回给调用者并保留句柄；部分流错误可能需退出进程丢弃，不能保证无限重试能成功。

主要常量：40 个 inode 和 40 个 dentry（均含根，硬链接消耗额外 dentry）、8 个专用/普通共享底层打开槽、每文件 4 个 extent、文件最多 1024 B、文件名数组 28 B、KV 值最多 512 B、最多 256 个 run。实际可用容量还受目录、索引、页分配和专用 CDC 切分影响；错误必须检查，不能从常量推断任意序列都一定可写满。

## 4. 同步与崩溃假设

- 未成功同步的修改**不承诺**故障后保存，也不保证一定丢失。成功的文件 `fsync` 在当前软件协议内先写入/请求持久化数据和元数据，再用双槽 checkpoint 的 8 字节提交词发布；`fsync` 失败不会被包装成成功。共享全局 KV memtable 的其他待处理项目可能被某次 seal 一起发布，故不能把未同步作为隔离保证。
- 全局 `sync()` 先等待 xv6 块日志，再在 PMFS 锁下遍历当时的普通 inode 共享缓冲并逐一同步；遇到错误返回失败。它不再通过额外 `struct file` 引用延长 fd 寿命；不是所有文件的单一原子事务，也不覆盖专用句柄中尚未同步的工作缓冲。普通 xv6 inode 的 `fsync` 复用这个全局 sync；原生 virtio 驱动没有实现等价的设备持久化 flush。
- 协议需要至少：缓存块写回到**所声明的持久域**、屏障顺序、提交词 8 B 故障原子性、映射有效及校验未碰撞等假设。默认仅触摸内存并执行 fence，**不实现实际缓存写回**。可选 `PMEM_ZICBOM` 发出 `CBO.CLEAN` 并假定 64 B 块、合法权限，但是否到达持久域由平台决定。
- 软件 oracle 在各已插桩切点杀死 QEMU，并以相同的共享 RAM 文件或实验性独立 NVDIMM 普通文件后端重新启动；它验证该进程终止模型下的读取结果，**不是**硬件缓存逐出/乱序/撕裂或物理掉电。独立规格模型覆盖有界提前逐出和负控，但没有追踪实际内核内存指令，也不证明所有实现路径正确。
