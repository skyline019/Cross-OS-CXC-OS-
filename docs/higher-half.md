# Higher-half 与活动页表接管

## 1. 为什么不能只修改链接地址

EFI 映像由固件装载。即使 PE `ImageBase` 链接为 `0xFFFFFFFF80000000`，固件仍会把它装入实际可用物理内存，并按“实际地址减首选地址”应用一次重定位。

此外，OVMF 会把内存中 OptionalHeader 的 `ImageBase` 改成实际装载地址。因此解析器接受：

- 链接时的 higher-half 首选基址；或
- 固件改写后的实际低基址。

仅把高地址别名映射到当前物理页也不够：绝对指针仍可能指向低映像，而且全局运行状态需要一致。

## 2. 二次重定位流程

### 第一次：固件装载

- 读取 `EFI_LOADED_IMAGE_PROTOCOL`，得到实际 `ImageBase/ImageSize`；
- 固件完成低地址重定位，内核按普通低地址 EFI application 启动；
- 初始化 PMM、direct map 和过渡根表。

### 准备高映像

1. 解析内存中的 DOS/PE/COFF/PE32+ 头；
2. 校验 `SizeOfImage`、section table 和 Base Relocation Directory；
3. 从 PMM 分配连续物理页作为高映像后备存储；
4. 按 PE section characteristics 建立高虚拟页权限；
5. 映射同一套物理栈到高栈地址，保留 guard；
6. 创建运行时根表，复制高半部分 PML4 项并清空低 256 项。

此阶段只分配和映射，不复制映像内容。

### 最后一次复制

所有 PMM 和页表分配完成后：

1. 将固件低地址映像的完整虚拟布局复制到高映像物理页；
2. 遍历 `.reloc` 块；
3. 对类型 0 跳过，对类型 10 `IMAGE_REL_BASED_DIR64` 加上：

```text
0xFFFFFFFF80000000 - actual_loaded_base
```

4. 遇到未知重定位类型立即失败；
5. 此后不再进行任何分配或状态准备，直接跳到高入口。

“最后复制”是关键：高映像因此取得最终的 PMM 空闲链、页表根物理地址、串口状态和其他全局状态，而不是准备早期的过期快照。

## 3. 切换顺序

1. 低地址 stage 2 计算高入口 RVA；
2. 汇编将 RSP 切换到高栈并调用高入口；
3. 此时过渡根表仍有低映射，可用于故障诊断；
4. 高入口重新安装高 GDT 和高 IDT；
5. 加载只含高映射/direct map 的运行时 CR3；
6. 归还旧过渡根页；
7. 检查权限、guard 和低映射确实消失；
8. 执行 `int3` 和全部自测。

高 IDT 必须先于低映射移除，否则异常入口仍可能指向不可达低地址。

## 4. 权限模型

| 区域 | Present | Write | Execute |
|---|---:|---:|---:|
| 内核 text/可执行 section | 是 | 否 | 是 |
| 内核 data/BSS | 是 | 是 | 否 |
| 只读 section/header/gap | 是 | 否 | 否 |
| 高栈 | 是 | 是 | 否 |
| direct map | 是 | 是 | 否 |
| 栈 guard | 否 | — | — |
| 旧低地址内核 | 否 | — | — |
| M8 SIPI code page（后续单独映射） | 是 | 否 | 是 |
| M8 SIPI 参数页（后续单独映射） | 是 | 是 | 否 |

`inspect_mapping()` 遍历四级页表并综合各级 Write/NX 位。启动测试不仅检查“页存在”，还检查实际有效权限。M8 只恢复两个专用 SIPI 低页，不恢复旧固件或低内核映射。

## 5. 迁移暴露并修复的问题

旧堆扩展曾把 PMM 返回的物理地址直接当指针。低身份映射存在时该错误被掩盖，移除低映射后立即触发页 fault。现在所有堆页都显式通过：

```cpp
pmm::physical_to_virtual(physical)
```

访问。这个阶段因此不仅是地址布局变化，也消除了隐藏的物理/虚拟地址混用。

## 6. 当前限制

- 运行时旧固件下级表与低映像不可达，但还没有纳入安全回收；
- 高内核地址固定，没有 KASLR；
- 只处理当前 GCC/MinGW 产生的 DIR64 重定位，未来新增其他类型必须显式实现；
- 四级页表、共享 runtime root、无 PCID/LA57；AP 的 32 位过渡要求 CR3 低于 4 GiB；
- 尚无用户地址空间和按需页权限修改 API。
