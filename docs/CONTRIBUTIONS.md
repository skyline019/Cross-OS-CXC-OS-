# 候选贡献、已实现组合与研究假设

> 这是可核验的工程组合和待检验假设，不是“算法首创”结论。证据和限制见 [VFS 验证记录](results/2026-10-28-vfs/README.md) 与[路线图](EXCELLENCE-ROADMAP.md)。

## 核心问题

在声明持久域、缓存块操作及故障原子性假设的前提下，如何在 xv6 中实现可恢复的字节寻址文件提交，并验证范围刷写能否降低相同语义下的软件开销？

| 候选贡献 | 计划交付 | 必须有的证据 |
|---|---|---|
| 受限 VFS + PMFS 组合 | 逐组件跨固定挂载点遍历、inode pin、独立 offset/共享缓冲、一次 checkpoint 发布目录子树 | 1/3 核功能、空间耗尽回滚、正常及切点重启、真实内核提前发布变异；缺原生/cross-backend rename、打开后 unlink 和可扩展并发 |
| 可重放故障检查 | 独立有界规格模型 + QEMU 进程重启切点 oracle | 模型提前逐出和多个负控；真实内核变异被抓；**尚未**接入实际 store/flush/drain 轨迹，也未覆盖全部并发/硬件故障 |
| 可重复软件测量 | 同数目、完整数据/EOF 校验，独立 QEMU 进程、相同输入磁盘 hash、逐启动样本及按启动 bootstrap | 当前仅 EMUL 小工作负载，持久契约不等价；还需同语义对照、更多规模/消融及原始路径计数，不能声称硬件性能优势 |

## 可检验的轻量化假设

设一个数据持久化阶段的设备窗口覆盖 `W/C` 个对齐缓存块，其中本次实际修改涉及 `K` 个不同块。全窗口扫描请求 `W/C` 个块；合并脏范围后请求 `K` 个块。两方案都必须计入额外的提交槽、跨阶段重复刷写和 drain；只有 `K < W/C` 的工作负载才预期减少数据阶段刷写请求。记录管理成本及 QEMU 模拟边界，不能把软件计数称为真实介质写流量。

## 与既有工作的关系

BPFS、PMFS、NOVA 等已有 COW/持久内存文件系统设计；CrashMonkey、PMTest、Witcher 等已有崩溃或一致性测试研究。论文需查证和引用原文，比较问题、故障模型、接口与覆盖范围；不能声称首创 COW、缓存刷写或自动崩溃测试。教学内核约束下的整合、可复现证据和实测效果，只有在完成实现后才能定稿为本课题贡献。

旧 `ONBOX_PMFS_*`、PMEM2 魔数和 A0–A4 表格只能作为原型 smoke/历史素材，不足以单独支撑以上贡献。
