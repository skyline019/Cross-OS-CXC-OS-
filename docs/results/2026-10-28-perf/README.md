# 同工作量延迟、短批吞吐与 GC 提示消融（软件仿真）

> 本次结果只适用于记录的 QEMU 9.2.0 TCG / 单 hart / Zig 交叉构建和本沙箱。PMFS 是**易失 EMUL 内存**，默认 `pmem_flush` 是 touch+fence；原生 xv6 使用块日志，`fsync` 为全局日志同步且驱动无等价的设备 flush。两者**持久契约不等价**，所以表中不能解释为真实持久内存相对块设备的优势，也不证明物理掉电安全或设备寿命。提示消融只比较同一个 PMFS 路径、同一个同步契约。

## 方法与原始数据

- 每组 1 次预热启动 + 10 次独立测量启动，单 hart、私有副本、顺序运行；每次启动先执行每后端 4 次预热，再执行每后端 32 次交替的独立计时事务。组顺序以固定种子打乱，事务的 PMFS/xv6 次序交替；失败将留在 `raw.jsonl` 且整次实验返回失败，本次 8 组均零失败。文件内容和 EOF 每次校验，变更覆写使用不同内容，不是相同写消除。
- `roundtrip` 每侧执行相同的“检查不存在、创建/打开、seek、write、fsync、close、重开、完整读回+EOF、close、unlink”；`overwrite` 每侧对已创建文件执行“打开、seek、变更写、fsync、close、重开、完整读回+EOF、close”。路径是各后端根下同等相对深度；`/pm` 本身的挂载遍历仍计入 PMFS 路径。1024 B 是当前 PMFS 文件上限。
- 在逐事务样本之后，两侧各顺序运行一个**实际计时的 32 次事务批**；批时间包含内容生成及循环、文件系统调用和校验，但不包含逐事务打印、单次计数器采样。批内和后端间无并发，后端顺序按启动轮换。吞吐为成功事务总数 / 批次 guest 时间之和；这是短批串行吞吐，不是长时稳态、多线程或宿主外部 wall-clock 吞吐。
- 客户端 `cycles()` 实际读取 RISC-V `r_time`，频率从该次 QEMU 生成的设备树 `/cpus/timebase-frequency` 得到 **10,000,000 Hz**。p50/p95 是 320 个样本的池化描述；95% 吞吐区间使用 2000 次**按独立启动重采样**（固定种子）。样本不足以作高置信 p99 或生产性能结论。
- [`matched/metadata.json`](matched/metadata.json)、[`matched/raw.jsonl`](matched/raw.jsonl)、[`matched/batches.jsonl`](matched/batches.jsonl)、[`matched/summary.json`](matched/summary.json) 和 88 份逐启动串口日志保留了预热及测量样本、失败信息、模型选择及二进制哈希。[`environment.txt`](environment.txt) 和 [`source-files.sha256`](source-files.sha256) 记录工具包装、环境和逐文件源码哈希；内核基于 `7b7d8d1` 加本轮尚未提交的工作树，故隔离构建中的 `git_commit` 为 `null`，不能误当成该提交的纯净构建。

## 两后端同 API 工作量（契约不等价）

| 工作负载 | 字节 | PM p50/p95 (ms) | xv6 p50/p95 (ms) | PM 短批 txn/s [95%] | xv6 短批 txn/s [95%] |
|---|---:|---:|---:|---:|---:|
| roundtrip | 8 | 2.140/3.737 | 21.812/33.151 | 467.3 [434.2, 497.1] | 45.2 [44.1, 46.1] |
| roundtrip | 64 | 2.127/3.105 | 21.773/27.012 | 483.7 [455.5, 507.5] | 44.4 [43.1, 45.7] |
| roundtrip | 512 | 2.225/3.930 | 21.856/29.245 | 455.4 [420.2, 486.5] | 44.7 [43.2, 46.2] |
| roundtrip | 1024 | 2.362/4.475 | 21.989/35.244 | 444.0 [426.7, 460.4] | 43.0 [40.9, 45.1] |
| overwrite | 8 | 1.476/1.908 | 7.479/9.294 | 704.7 [648.1, 750.4] | 125.7 [116.3, 134.1] |
| overwrite | 64 | 1.478/2.259 | 7.507/9.972 | 700.3 [657.0, 732.8] | 129.6 [124.0, 134.8] |
| overwrite | 512 | 1.659/2.616 | 7.642/10.786 | 655.4 [642.2, 669.0] | 130.2 [126.5, 133.4] |
| overwrite | 1024 | 1.791/2.188 | 7.437/9.846 | 583.6 [571.2, 593.9] | 130.5 [121.8, 136.6] |

负结果/代价：此软件样本中 PMFS 的 1024 B 覆写短批吞吐低于 8 B（583.6 对 704.7 txn/s），创建+删除事务低于覆写；32 页设备完全满盘时，压缩仍因缺少不相交空间安全失败。软件 PMFS 每个测量覆写请求约 8320 写字节、每个 roundtrip 约 24832 写字节；这些只是软件 `pmdev_write` 和提交词请求，不是物理写放大或擦除数。

## 同 PMFS 同步契约：可达性缓存传播提示消融

启用版和 `-DPMFS_GC_NO_HINTS` 控制版由**相同源码及相同 fs.img** 构建，启动时确认相反标记，均保留双槽检查、COW 写和同一 `fsync`；只关闭已验证 run 可达位图向新槽的传播提示。每组 10 个配对测量启动（另 1 对预热），配对构建次序轮换，32 次逐事务样本和 32 次短批事务。区间对**启动对**重采样；[`gc-hints/`](gc-hints/) 保存全部原始样本、串口和结果。

| 变更覆写 | 启用/禁用 PM p50 (ms) | 启用/禁用短批 txn/s | 吞吐比 [配对 bootstrap 95%] | 每事务软件读请求字节 启用/禁用 |
|---|---:|---:|---:|---:|
| 64 B | 1.475 / 3.526 | 678.8 / 160.3 | 4.235 [3.883, 4.555] | 12,480 / 356,544 |
| 1024 B | 1.788 / 3.848 | 569.9 / 150.5 | 3.787 [3.585, 4.037] | 41,152 / 385,216 |

这表明**本负载、仿真及较长链短批**下，关闭提示引入了大量可达性重新读取；不能推断其他访问分布、缓存层级或真实器件上的相同倍率。两组软件写请求均为每事务 8320 B；消融不证明降低实际硬件写入量。比值是在本样本的有限条件下估计，不是持久性证明。

## 复现

在两个隔离 checkout 中分别清理构建 default EMUL 与 `EXTRA_CFLAGS=-DPMFS_GC_NO_HINTS`，确认源码和生成的 fs.img 一致，然后运行：

```sh
python3 tools/bench_perf.py --runs 10 --warmup 1 --samples 32 \
  --sizes 8,64,512,1024 --modes roundtrip,overwrite --output /tmp/pmfs-matched
python3 tools/bench_gc_hints.py --enabled-root /path/enabled --disabled-root /path/disabled \
  --runs 10 --warmup 1 --samples 32 --sizes 64,1024 --output /tmp/pmfs-hints
```

构建会重建镜像，请只在可丢弃 checkout 中运行。沙箱未做 CPU 隔离、调频或噪声控制；不得把本记录填入旧论文中宣称真实硬件持久性能的表格。
