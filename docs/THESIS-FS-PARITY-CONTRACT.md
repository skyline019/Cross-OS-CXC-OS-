# 完整 VFS/API 与持久语义：硬目标和当前阻塞

> **状态：未达成。** 本文是目标和验收约束，不是现有功能声明。无 KV/CDC 的 `directcore` 目前仍只有 512 B 单对象的实验 syscall，既不是普通 fd 文件系统，也没有目录。旧 v3 PMFS 保留，但不能充当新的直接 PMEM 后端。不得用两者的共同子集、缩小文件、伪造后端或降低故障语义来宣布对等。

## 1. 对等对象与不可降级范围

- 对照为 **QEMU NVMe 上的原生 xv6 文件系统**；目标是 **独立 QEMU NVDIMM 上、直接字节寻址、无 KV/CDC 的 PMEM 文件系统**。需要同一普通 VFS/syscall 路径和可复现的设备身份，不能通过 `directcore()` 或专用 `pmfs_*` 绕过普通文件 API。旧 KV/CDC 代码及其格式仍保留，不能在同一介质上与新格式混用。
- 基础接口至少包括普通 `open`/`read`/`write`/`lseek`/`fstat`/`dup`/`close`、`fork` 共享打开对象、追加和截断、硬链接、打开后删除最后链接、文件与目录、路径解析、工作目录、目录枚举、`mkdir`/删除、同文件系统完整 `rename`、设备节点及 `exec`。跨文件系统 `link`/`rename` 必须失败且无副作用，不得偷偷复制后删除。
- 完整 VFS 扩展还包括符号链接及不跟随链接的操作、非零长度截断、映射、权限及动态挂载等。目前相关普通 syscall/实现缺失，**是阻塞项**，不是自动跳过项；本项目当前 xv6 ABI 只返回 `-1`，也不能宣称已经实现 POSIX 的完整 errno 或全部 Linux 语义。
- 不得靠更低资源上限取得对等。新后端必须支持至少原生格式现有的 268 × 1024 = **274432 B** 单文件、直接/间接边界、多文件多目录和近满盘场景，且不能以 40 inode、27 B 整路径或 1024 B 文件充当正式上限。原生 14 字节分量静默截断本身也不是可接受的完整 VFS：两端都需支持并验证至少 255 B 不冲突名称、至少 4096 B 路径，以及配置足够空间时超过 4 GiB 的 64 位文件偏移/大小；若底层介质较小，必须区分真实 ENOSPC 与人为缩小 ABI。文件数、目录数和 fd 限制须由明确的共享内核/介质资源决定，并覆盖可达极限和释放后复用。
- `O_APPEND` 的每次成功写入必须对同 inode 其他普通写入表现为一个连续记录，含超过单事务上限的写入；`dup`/`fork` 的共享 offset 与独立 `open` 的独立 offset 必须正确。部分用户缓冲区无效、文件大小上限及真实 ENOSPC 时，返回实际完成的前缀；失败前不能无报告地更改其他数据。稀疏洞读为零且不应因读取分配空间。
- 目录移动、替换、非空/类型不匹配拒绝、同 inode 重命名 no-op、循环检测、`..`、链接数、打开目标和并发读者等均需正确；崩溃不能留下半个 rename。当前原生 rename 仅同目录、目标不存在的普通文件，长名仍截断，都是明确阻塞。

## 2. 共同确认点：目标契约

“对等”指在**相同声明的故障模型**下提供相同的最低保证与允许结果，而不要求未同步修改必然丢失；某实现提前提交不改变此契约。不能因单线程通常提前提交，就声称每次 `write` 返回均已持久。

1. 一个 `write` 成功返回 `n > 0` 表示这 `n` 字节及 offset 已对正常运行中的观察者生效；未经后续成功同步，不承诺崩溃后保留，也不承诺一定丢失。大写入可以分事务，因此未同步崩溃时可能只保留满足已提交事务顺序的前缀；不能把整次大写自动声称为掉电原子。短写返回 `n` 时，同步和恢复针对实际返回的 `n`，而不是请求长度。
2. 成功的 `fsync(fd)`（含只读普通文件和目录 fd）是所属后端的持久屏障：在调用前已完成并先行于它的相关写入、大小/截断和元数据在声明的持久域中可恢复。必须包含成功返回前已完成的操作，即便它们与其他操作共享事务；允许包含并发或较晚提交的其他操作。当前原生日志屏障是全盘级，目标直接后端须提供不弱于此的确认保证，不可用仅刷新某个缓存行冒充。
3. `fsync(file)` 保证文件内容、大小及访问该 inode 所必需的元数据；要保证创建/删除/rename 的名字与目录关系，调用方需成功 `fsync` 所有受影响的父目录。后端可以提前或顺带提交更多名字，但测试不得依赖未经确认的名字必然消失。`sync()` 成功则须覆盖调用前已完成的各已挂载后端操作；它不是跨设备单一原子事务。
4. 同一后端的 rename/link/unlink/创建等已提交命名空间事务必须满足图不变量；rename 一次生效或完全不生效。最后链接删除后的打开 fd 在运行时仍可读写；重启后无存活 fd，未链接 inode 可回收。文件/目录 fd、cwd 和读者保护不得导致重用仍可见的旧版本。
5. `close` 不是替代成功 `fsync` 的可靠持久确认；失败不得静默伪报成功。空间耗尽、无效用户地址、设备 I/O/flush 错误及恢复损坏都须有明确、可观察的失败行为，已确认数据和命名空间不受后续失败破坏。**当前 NVMe 错误多为 panic，尚未满足错误传播要求。**
6. 原生 `end_op()` 可以在别的事务仍活动时先返回；当前 `log_sync()` 阻止新的日志操作无期限插队并等待已活动事务及提交。直接后端需实现同等的有序屏障，而不是给基准单独添加 `fsync` 后宣称全部 API 等价。不同后端的存储容量配置及目录/数据确认点必须写入实验报告。

## 3. 故障模型和必须的证据

当前结算环境是 QEMU 模拟，不把物理硬件当作已验证：

- NVMe 在所测试的 QEMU 文件后端使用显式 Flush；virtio 目前未协商 flush，**不具备相同设备持久契约**。
- NVDIMM 的持久化声明必须列出映射、缓存行大小、store 原子性、flush/fence 和持久域假设。QEMU TCG 不模拟真实持久缓存层次；普通宿主文件与 QEMU 进程 SIGKILL 不等同整机掉电。可注入源码级 store/flush/drain 边界并重放明确的持久化候选，但不应冒充逐指令、所有重排或物理断电证明。
- 必须对**两端**分别覆盖确认前后、不同大小/非对齐、稀疏间接边界、目录依赖、rename/link/unlink、未同步允许状态、短写/满盘、并发确认、打开后删除、读者保护/回收和故障后继续写入；需要独立介质图检查、实际内核轨迹、负控（如故意丢失提交或屏障）及原始日志/构建和镜像哈希。每种范围、边界、设备身份和故障注入覆盖率要明确列出。任何缺失、跳过或不可信报告都不能变为 PASS。

## 4. 可执行门禁与现状

- `user/fsparity.c` 用同一组普通 API 对一个新建的可丢弃目录执行探测；`tools/fs_parity_probe.py` 保存串口结果。当前 14 个实际案例外加 5 个明确 `BLOCKED` 扩展，并不穷尽第 1–3 节。每个案例后清理命名空间，避免小容量后端耗尽后其余案例根本没有运行。
- `tools/fs_parity_gate.py --native-report ... --direct-report ...` 严格要求所有已列案例存在且 PASS，拒绝缺项、重复、错误汇总、截断标记或 BLOCKED；它还**硬性阻塞**未实现的设备身份和独立持久性验证器。即使人为提供两份全 PASS 的 API 日志也不能通过。要解除任一阻塞，必须先增加真正可执行的独立 oracle 和负控，而非仅修改一个标志或提供声明性 JSON。
- `tools/check_native_api_regression.py` 只保护 12 个当前原生探测行为，明确不是总验收；`tools/native_sparse_recovery.py` 是原生 NVMe/virtio 的稀疏、短读写、真实 ENOSPC、块位图和日志屏障回归，**不是直接 PMEM 的持久 oracle**。
- 三核 QEMU 上当前原生普通 API 探测：**12 PASS、2 FAIL（完整 rename、长名）、5 BLOCKED**；旧 v3 PMFS 在同一严格程序上为 **0 PASS、14 FAIL、5 BLOCKED**（易失 EMUL，仅作负例），不用于冒充目标。上述数字只是这一组用例，不是功能完备率或性能结论。
- 直接 PMEM 真正的多 inode/多目录 VFS、64 位数据布局、普通 fd、空间回收与读者保护、完整元数据事务、持久屏障及双方故障差分均未完成。正式的等价延迟/吞吐实验必须等总门禁有真实证据且通过后，采用相同 API、资源配置和确认点重新运行；历史 directcore 特殊 syscall 数据不能当作该结论。
